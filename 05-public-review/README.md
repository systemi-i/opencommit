# Public Review Guide

ICSL v0.1 is being prepared for external consultation.

The goal of public review is to test whether the candidate standard is conceptually clear, technically implementable, institutionally realistic, and useful for public-service interoperability, AI governance, and digital public infrastructure.

## What To Review

Reviewers are invited to assess:

- the conceptual model;
- protocol and commitment semantics;
- six-gate completeness;
- authority, evidence, binding, recourse, and versioning rules;
- package format;
- conformance classes;
- schema enforceability;
- AI and civic-agent boundaries;
- implementation feasibility;
- risks of overclaiming or ambiguity.

## How To Submit Feedback

Feedback should identify:

- the affected document or section;
- the issue type;
- why it matters;
- a concrete example if possible;
- whether it should block v0.1 or be tracked for later.

Use the feedback intake guide for triage categories and suggested formats.

## Review Posture

This is a candidate standard, not a finished standard.

Critical feedback is welcome. The review process should identify where the model is strong, where it is unclear, where it may overclaim, and where implementation would fail under real institutional conditions.
